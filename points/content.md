# 内容

- 为什么很多人的第一个网站是自我介绍
- 为什么拿网站做练习台：浏览器零门槛、改完立刻看得到；背后讲顺眼顺手的规律，换到 App、桌面软件甚至硬件面板照样成立
- 为什么全书先讲内容，而不是配色和排版：很多界面怎么调都别扭，根因不在 CSS 功底，而是内容本身没想清；界面是替内容和任务搭架子，内容立住了，后面的划分、尺度和风格才不虚
- 先写字，再开画板和写 CSS
- 关掉样式的纯文本测试：只剩黑白文字还成立吗
- 关 CSS 同时也是语义骨架测试：全用 `<div>` 堆出来的页面关掉样式会塌成一坨，而诚实使用标题、段落、列表、链接和按钮表达关系时，零样式就自带秩序，也顺手替读屏器、键盘和复制粘贴打好了地基
- 抽掉视觉外壳看信息骨架：网页关 CSS，原生 App 看读屏顺序，命令行看纯文本输出能不能自洽
- 只有模板空壳、没有真东西的空洞感
- Lorem ipsum 与“完美假数据”的陷阱
- AI 时代的新一代 Lorem ipsum：看似通顺的 SaaS 八股（“赋能下一代……”“极速 / 安全 / 智能”三栏）和字数工整、头图齐全的模拟数据，全是真中文却依然零信息量，一接真实业务照样塌房
- 个人主页典型假内容：技能百分比进度条、空洞口号、凑数三栏卡片
- 用证据和具体细节代替形容词与自夸（Show, don't tell）：写做了什么工具、解决了什么问题、附链接和成品示例，而不是“热爱开源、精通 React 90%”
- “为了不显得空”硬凑出来的装饰语和无意义图标
- 没真图宁可留白，别塞毫无信息量的抽象渐变或廉价装饰插画；值得放上页面的真图是界面实拍、前后对比和作品成品
- 动态内容的“维护债”：只开你养得活的坑，没有持续产出就别硬搭带归档和标签云的博客、动态或“正在听”栏位，免得三个月后成废墟；软件里过期的公告和精选同理
- 一页只扛一个核心意图
- 用一句话写清：这页给谁看、让人干嘛
- 先分清网站或页面占了哪些性质，再决定首屏摆什么、怎么取舍
- 人的属性（身份与气质）：个人站把名字放大、保留个人趣味完全成立，别写成冷冰冰的说明书
- 内容属性（阅读与理解）：一切装饰给行宽、字阶和连续阅读秩序让路
- 展示属性（门面与说服）：强调节奏、留白与印象（如产品叙事），但别拿它硬套工具和文档
- 检索属性（查找与筛选）：东西一多，核心是让人最快扫到和筛出要的那一条
- 工具属性（操作与完成任务）：少废话直奔工作台，死磕操作省力、反馈与容错
- 现实里的网站往往是几种性质按比例混合，最忌拿同一套模板公式硬套所有页面
- 混合性质必须分主副：由唯一主属性定骨架，副属性只做点缀不挡路；工具可以带一点“人的趣味”，前提是核心任务流稳妥清晰，别让展示炫技或玩梗盖过干正事
- 检索和工具性质做深了，长相早就不再是传统“网页”，而是软件工作台
- 人在屏幕上大多是扫读（Scanning）而非逐字精读：进页前 3 秒心里只问“这是什么、跟我有什么关系、我能干嘛”，视线专抓标题、数字、具体名词和入口；结论前置，干掉“欢迎来到我的网站……”这类客套废话（Happy Talk）
- 写字阶段就分出信息主次（内容层级先于视觉层级）：先定谁是主角、谁是配角、谁是注脚、谁该删掉；视觉层级只能放大内容里本来就存在的主次，没法凭空造出主次
- 按读者最在乎的顺序排内容，别按自己的实现顺序
- 真实数据压力：1 个字、40 个字、0 条、500 条
- 可选字段缺省：没头像、没副标题、没封面图时怎么长
- 不可控的脏数据同样要在原型阶段验货：真实软件里的内容往往来自用户和接口，除了长短与缺省，还要拿无空格长 URL/代码串、一堆“未命名”同名项、横竖混排的上传图去测，别被精修的 3 条样本骗了
- 砍掉一半废话后，界面自己就会变顺眼
