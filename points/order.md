# 排序

- 默认排序才是最重要的排序，别把选择难题全扔给用户
- 默认按“用户打开后最想看或最可能点”的内容排
- 列表顺应人直觉：消息最新在上，教学或步骤第一步在上
- 导航和菜单顺序：高频在最顺手位，低频和设置沉底
- “最顺手位”因设备而异：手机在单手拇指区，桌面在视线落点和默认焦点附近，危险或低频项离远点
- 弹窗和表单底部按钮的排列顺序与主次位置
- 确认和取消放左还是放右，顺着所在平台用户的肌肉记忆走（比如 macOS 与 Windows 习惯相反），重点是视觉主次必须分明
- 危险按钮别跟主要确认按钮长得一样还贴在一起
- 表单提问顺序先易后难，开头给好填的建立填写惯性
- 下拉框里把常用几项提上来，别死按拼音或数据库 ID 排
- 序列位置效应：一排导航或 Tab 里，首尾最醒目、中间最易被忽略；把核心主入口放首位，我的/设置/主收口放末位，次级入口放中间
- 空间稳定性高于“智能重排”：结构性导航、高频工具和菜单的位置要钉死，绝不按最近使用频率动态挪动破坏肌肉记忆；想照顾刚用过的项，单独在顶部划一小块“最近使用 / 常用”区，下方完整列表保持固定可预测顺序
- 操作后别瞬间把条目“弹飞”（延迟重排）：在待办或未读列表里勾选完成/已读时，先原地置灰或给缓冲期再重排，既方便反悔，也防止误点顶上来的下一条
- 人眼自然序 vs 机器排序：用自然排序（`第 2 章` 排在 `第 10 章` 前，别排成 `1, 10, 2`）；有天然语义顺序的（星期、月份、高/中/低、尺码、流程状态）绝不按拼音或字母排
- 空值永远沉底 + 稳定次级排序：无论升降序，未填写或无截止日期的空值都不该冲到第一行；主排序值相同时必须有确定的次级规则，防止刷新翻页来回跳位
- 区分两种时间流方向：通知、邮件、动态流最新在上（先扫最新）；聊天对话、终端日志最新在下（顺着从上往下的对话流阅读，输入框贴着最新一条）
- 表格列顺序与单行信息序：第一列/最左侧永远是“这行是什么”（主标识/名称），其次是核心状态与关键数值，辅助元数据靠后，行内操作收在最右端
- 置顶（Pin）与手动拖拽排序的边界：只有用户主观定义优先级的列表（待办、歌单、看板）才适合手动排序，客观维度列表别硬加拖拽；置顶项要单独分区并限制数量，全员置顶等于没置顶
- 排序控件的显式表达与点击直觉：让人一眼看清当前按什么排、升序还是降序（包括“推荐排序”也要明示）；点击表头首次切换顺应数据类型（日期/数量/金额常先降序，名称先升序）；排序项别拆成十几个“某字段升/降”的长下拉，可拆成“排序依据 + 正/倒序”
- 一屏（或一个区块）内动作的视觉权重排序：最多只留一个主按钮（Primary），其余降级为次要或文字按钮；窄屏纵向堆叠按钮时顺应阅读流与拇指可达区，别死搬桌面左右习惯
- 视觉顺序必须与键盘 Tab 焦点及逻辑顺序一致，别靠 CSS `order` 或 `row-reverse` 把两套顺序拧反
