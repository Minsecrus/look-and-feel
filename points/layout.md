# 划分

- 只有一百多字真内容时，不需要顶部五个导航栏
- 一页装得下就别拆页，撑爆了再分页
- 什么时候开独立页面：完整心流、需要独立链接分享、需要浏览器后退
- 独立页面背后的通用概念是“可往返的上下文栈”：Web 靠 URL 和后退，App 靠导航栈与手势返回，向导软件靠上一步
- 什么时候用抽屉或弹窗：顺手新建或修改，做完立刻回原处
- 什么时候行内原地展开：高频微调、边改边看结果
- 别把一件事拆成五步来回跳，也别把五件无关的事全堆一屏
- 一页里的三种角色：舞台（主体）、路标（导航定位）、控制手（操作）
- 路标老实待在边缘，绝不比舞台喧宾夺主
- 操作离它控制的对象越近越好
- 物理世界里叫“自然映射”：就像灶台旋钮紧挨着对应炉头，桌面编辑器、仪器面板和网页都怕控制手跟舞台隔太远
- 一屏能一眼辨认的区块最好不超过 3～4 块
- 边界的轻重顺序：留白 → 浅底色差 → 细分割线 → 完整边框
- 能用留白隔开的先别画线，能用底色隔开的先别套框
- 避免“卡片套卡片套卡片”的套娃盒子
- 按这页的具体内容去隔房间，别死套现成模板骨架
- 容器打断程度的完整梯度：原地行内 → 气泡浮层（Popover）→ 侧边抽屉（Drawer）→ 模态弹窗（Modal）→ 独立页面，优先选轻容器，尽量保住用户脑中已建好的空间地图，少做无谓的场景切换
- 抽屉与弹窗的分工及禁忌：抽屉适合需要一边对照背后内容一边查看或较长编辑，模态弹窗只留给必须先做决断的强打断；绝不弹窗套弹窗
- 导航放顶部还是放左侧：3～5 个固定入口的展示或阅读页适合顶栏；入口多、有层级树或允许用户动态增删项目的工作台适合侧边栏
- 高频在多条记录间来回切换对照时（邮件、笔记、聊天、工单），用“左列表右详情（Master-Detail）”代替列表页与详情页反复进出
- 跨页的空间恒常性：切换页面时路标和核心控制位钉在固定坐标不动、只换舞台，帮用户建立空间记忆（就像汽车仪表盘和方向盘拨杆位置从不乱动才能盲操）
- 上下文往返必须保留现场：从列表进详情再退回，滚动位置、展开状态和筛选条件原封不动留在原地，别一返回就刷回顶部
- 避免“假底陷阱（False Floor）”：别让首屏底部刚好留出工整切口或大片空白让人以为到底了，适当让下一区块露半截就是最自然的滚动信号
- 谁该固定（Sticky）、谁该跟着滚：表头、目录、长表单提交栏可按需固定，但吸顶加吸底别把舞台压成坦克观察孔；忌讳一屏内套出多个互相打架的局部滚动条（滚动陷阱）
- 主副栏宽度分配与伸缩边界：导航侧栏定宽、主舞台弹性铺开，避免主内容被挤成窄缝；阅读与短表单锁死合适宽度（别让 4 个输入框横跨 1400px），大表格和画布放开铺满；工作台侧栏允许折叠或拖宽
- 自然映射不只看距离，还看形态和方向与结果的直接对应：比如车门上做成座椅形状的调节键、滑块往右或向上拉为增大，不用看字就能盲操
